# D5（2026-11-20）定时任务小实验：Cron100 → Sepolia，最多 2 次

这份说明给 Windows PowerShell 用。合约、测试和脚本都在仓库里，部署要在你自己的电脑上跑。这里没有填交易哈希。公开网络上没有部署。本地用 Foundry 1.9.0 对 Lasna 和 Sepolia 做了分叉，只在 `127.0.0.1` 上跑过四个脚本：部署 Reactive、部署 Callback、`setRecipient`、`stop`，并确认脚本会拒绝旧的 D3/D4 地址。分叉上的合约地址不能当作业地址。没有读取私钥。

## 这次做的是哪条链路

```
Lasna Cron100（约每 100 个区块）
        │  D5CronReactive.react()
        ▼
Lasna 请求回调（SYSTEM.requestCallbackV_1_0）
        │  Sepolia Callback Proxy 投递
        ▼
Sepolia D5CronCallback.onTick()  发出 Ticked
```

第 2 次请求回调时，同一笔 `react()` 会按订阅时的六个参数调用 `unsubscribe`。之后 `subscribed = false`、`stopped = true`、`remaining = 0`。再送来的 tick 只更新 `lastCronNumber`，不再调用 `requestCallbackV_1_0`。

官方仓库里没有可以直接交作业的脚本：

- 本仓库原来的 `starter/script/Deploy.s.sol` 监听的是 `Ping`，不是 Cron。D3/D4 的 `CampOrigin`、`CampReactive`、`CampCallback` 这次没有改。
- `reactive-smart-contract-demos` 主分支的 `src/demos/cron/CronDemo.sol` 使用 `vmOnly` 和 `emit Callback`，那是旧架构。
- 同仓库 `omni` 分支的 `src/micro-demos/Cron.sol` 是现在要跟的写法：`AbstractReactive`、`onlySystem`、`SYSTEM.subscribe`、`requestCallbackV_1_0`，并有 `pause()` / `unsubscribe`。它的回调目标是 Lasna 上的自己，没有 Sepolia 合约，也没有「最多 N 次」。`CRON.md` 只有部署、暂停、恢复三条命令。

本实验把 Omni `Cron.sol` 的 Cron100 常量和退订方式，接到本仓库已有的 Sepolia 回调写法上，并把上限做成构造参数，部署脚本默认是 2。

2026-11-20 在 Lasna 上读过 Cron100 日志（只读）：`topic0` 是 `keccak256("Cron100(uint256)")`，`data` 为 `0x`，区块号在 `topic1`。相邻两次（区块 8813600 与 8813700）的时间戳相差 105 秒。文档里「number 在 data」的说法和这条链当前的事件不一致，合约两种布局都解码，优先用 `topic1`。

## 先补测试币，再部署

只读查过测试钱包 `0x5576d42Fe13888b7f084190934abD07F061225fe`（2026-11-20，余额之后会变）：

| 链 | 当时余额 | 这次怎么用 |
|---|---|---|
| Ethereum Sepolia | 约 0.0199 ETH | 不够同时支付部署 gas 和给新回调合约存 0.02 ETH |
| Lasna | 约 0.471 lREACT | 够部署。脚本默认把其中 0.15 lREACT 存进新合约 |

已有的 D3/D4 合约不要动。当时 Lasna 上的旧 Reactive `0x9a30c9bc9c6dC4101679A735e121e3856cC12FB6` 自己还持有约 0.456 lREACT，`remaining = 4`，`debt = 0`。那笔余额不在钱包里，Ping 才会消耗它。旧 Sepolia 回调 `0x9bebaFE458DaF45faB88Abd42A2Efc36B38A7A32` 仍有约 0.02 ETH，`count = 1`。

建议在开始前让钱包达到：

- **Sepolia ETH：0.05 ETH。** 现在大约 0.0199 ETH，不够再转出 0.02 ETH。部署回调时脚本默认随合约转入 **0.02 ETH**，用来付两次回调的 gas。本地 Sepolia 分叉上这笔部署实际用了 2,431,043 gas，按当时约 0.05 gwei 的价格，手续费大约 0.00016 ETH；真正占余额的是那 0.02 ETH。旧回调在一次真实回调之后几乎仍是 0.02 ETH，所以 0.02 ETH 对这种只写三个存储的回调是够的。水龙头暂时只够 0.03 ETH 时，可以把环境变量改成 `10000000000000000`（0.01 ETH）再部署。
- **lREACT：先别换币，钱包里的约 0.47 够这一次。** 脚本默认把 **0.15 lREACT** 放进新合约，这笔钱只付 react，不付部署交易。部署交易的 gas 从钱包扣。本地 Lasna 分叉上（没有广播到公开网络）`DeployD5Reactive` 的 gas 估算是 1,108,762，forge 按 200 gwei 的费用上限大约预留 **0.222 lREACT**；`setRecipient` 实际用了 80,456 gas，费用上限大约 **0.02 lREACT**。0.15 + 0.222 + 0.02 ≈ 0.39，低于当时的 0.47。合约里的 0.15 相对速查表「一笔简单 react 约 0.015 lREACT」还有余量：两次 tick 大约 0.03。若 forge 报余额不足，把预存改成 `100000000000000000`（0.10 lREACT）再部署。还想多留，再向水龙头转 **0.01 ETH** 换 **1 lREACT**。单笔不要超过 5 ETH。部署前看 forge 打印的 `Estimated amount required`：那是 gas 费用上限，还要另外加上随合约转入的 0.15。

水龙头合约（Ethereum Sepolia）：`0x9b9BB25f1A81078C544C829c5EB7822d747Cf434`。1 ETH 换 100 lREACT。

## 部署顺序

1. 本地测试（不需要私钥，不联网也可以，除了第一次下载 solc）。
2. 确认 `.env` 里已有 `PRIVATE_KEY`、`SEPOLIA_RPC_URL`、`LASNA_RPC_URL`、`CALLBACK_PROXY`。不要把 `.env` 贴到聊天、提交或截图里。
3. Lasna 部署 `D5CronReactive`。这一步不订阅。
4. Sepolia 部署 `D5CronCallback`。构造参数是官方 Proxy 和第 3 步的地址。
5. 回到 Lasna 调 `setRecipient`。这一步才订阅 Cron100。
6. 等大约 5 分钟。中间不用发 Ping，也不用再发交易。
7. 跑 `verify-d5.ps1`。`executed = 2`、`subscribed = false`、Sepolia `count = 2` 就可以把交易链接抄进作业。
8. 只有 `subscribed` 仍是 `true` 时，才跑 `StopD5`。

`DeployD5Cron.s.sol` 会拒绝这三个旧地址，并且在 `setRecipient` / `stop` 之前读 `MAX_EXECUTIONS()`，避免对旧的 `CampReactive` 调用同名函数。

## PowerShell 命令

在 **Windows PowerShell** 里整段执行。命令行里没有私钥；`forge script` 从当前进程的 `PRIVATE_KEY` 读取，和原来的 `Deploy.s.sol` 一样。不要加 `--private-key`，否则密钥会进历史记录。

```powershell
Set-Location -LiteralPath "D:\reactive camp\reactive-builder-camp\starter"
forge test --match-path test/D5Cron.t.sol -vv

function Import-DotEnv {
    param([string]$Path)
    foreach ($raw in Get-Content -LiteralPath $Path) {
        $line = $raw.Trim()
        if ($line.Length -eq 0 -or $line.StartsWith("#")) { continue }
        $eq = $line.IndexOf("=")
        if ($eq -lt 1) { continue }
        $name = $line.Substring(0, $eq).Trim()
        $value = $line.Substring($eq + 1).Trim().Trim('"').Trim("'")
        Set-Item -Path "Env:$name" -Value $value
    }
}
Import-DotEnv -Path ".\.env"

# 可选：覆盖默认金额。单位是 wei。不设置就用脚本里的 0.15 lREACT 和 0.02 ETH、上限 2。
# $env:D5_REACTIVE_FUND = "150000000000000000"
# $env:D5_CALLBACK_FUND = "20000000000000000"
# $env:D5_MAX_EXECUTIONS = "2"

forge script script/DeployD5Cron.s.sol:DeployD5Reactive --rpc-url $env:LASNA_RPC_URL --broadcast --chain 5318007
```

把输出里的 `D5_REACTIVE_ADDR=` 追加进 `.env`。用 `Add-Content`，不要用 `Set-Content`，后者会把整个 `.env` 覆盖掉。

```powershell
Add-Content -LiteralPath ".\.env" -Value "D5_REACTIVE_ADDR=0x把上面输出的地址贴在这里"
Import-DotEnv -Path ".\.env"

forge script script/DeployD5Cron.s.sol:DeployD5Callback --rpc-url $env:SEPOLIA_RPC_URL --broadcast --chain 11155111
```

再追加回调地址，然后绑定。绑定成功后 Cron 才开始，大约 2 分钟内会有第一次 tick。

```powershell
Add-Content -LiteralPath ".\.env" -Value "D5_CALLBACK_ADDR=0x把上面输出的地址贴在这里"
Import-DotEnv -Path ".\.env"

forge script script/DeployD5Cron.s.sol:SetD5Recipient --rpc-url $env:LASNA_RPC_URL --broadcast --chain 5318007
```

等待时可以看这两个页面（地址换成你自己的）：

- `https://lasna.reactscan.net/address/<D5_REACTIVE_ADDR>`
- `https://sepolia.etherscan.io/address/<D5_CALLBACK_ADDR>`

大约 5 分钟后核对。这个脚本只调用 `cast call` / `cast logs`。

```powershell
powershell -ExecutionPolicy Bypass -File ".\script\verify-d5.ps1"
```

紧急退订（自动停止已经生效时不必跑）：

```powershell
forge script script/DeployD5Cron.s.sol:StopD5 --rpc-url $env:LASNA_RPC_URL --broadcast --chain 5318007
```

## 为什么不会一直扣到余额耗尽

Cron 订阅只要还在，每个 tick 都会收费，即使 `react()` 里什么都不做。所以有四层止损：

1. **部署时不订阅。** 订阅发生在 `setRecipient`。部署回调合约的那几分钟不会烧 lREACT，也不会把 2 次额度用掉。
2. **上限是 2，而且写死在 `MAX_EXECUTIONS`。** 没有增加次数的函数。第 2 次请求回调之前就把 `remaining` 减到 0，并用和订阅完全相同的参数 `unsubscribe`。
3. **退订之后再进来的 tick 直接 return。** 不调用 `requestCallbackV_1_0`。节点正常的话，退订之后就不会再投递；万一有一笔已经在路上，这一层也不会再发回调。
4. **`stop()` 可以手动退订。** 只有主人能调，重复调用是空操作。跑完 2 次之后 `subscribed` 已经是 false，就不必再调。

不要改用 Cron1 或 Cron10。Cron1 大约每秒一次，在你发现没停之前就会把测试币扣掉。本实验只有 Cron100。

回调那边的 ETH 只在真正投递时支付。`onTick` 不因为「已经两次了」而 revert，因为失败的回调也收费。停止请求是 Lasna 合约的责任。

## 本地测试覆盖

`forge test --match-path test/D5Cron.t.sol -vv` 覆盖：

- 链不是 Lasna、或上限为 0 时，构造函数失败
- 绑定回调地址之前不订阅；绑定后只订阅一次 Cron100
- `react()` 只接受系统合约；别人不能 `setRecipient` / `stop`
- 直接调用 `onTick` 失败；Proxy 注入了错误的 reactive 地址也失败
- 第 1 次用线上的 topic1 布局，第 2 次用 data 布局，都会请求回调；第 3 次不再请求
- 退订的六个参数和订阅相同
- payload 第一个地址是 `address(0)`，目标链是 Sepolia，gasLimit 为 300000
- 不发出已经废弃的 `Callback` 事件
- `stop()` 之后再来 tick 不再请求；停止后不能再 `setRecipient`
- Mock Proxy 投递两次后，回调合约 `count == 2`

## 常见情况

| 现象 | 处理 |
|---|---|
| `WrongChain` | RPC 不是 Lasna。命令里保留 `--chain 5318007` |
| Lasna `lastReactBlock` 一直是 0 | 还没到下一个 100 的倍数区块，或 `setRecipient` 没成功。等满 5 分钟再查 `subscribed` |
| `executed` 增加了，Sepolia `count` 仍是 0 | 回调合约没有 ETH、Proxy 不是 `0xAa14…`、或 `D5_REACTIVE_ADDR` 填错。填错 reactive 地址只能重新部署回调合约，再重新 `setRecipient` |
| `debt` 大于 0 | 给该合约转对应的测试币，或调用 `coverDebt()` |
| 5 分钟后 `subscribed` 仍是 true，而且 `executed` 已经是 2 | 跑上面的 `StopD5` |
| 想再做一轮 | 重新部署一对新合约。不要给这个合约加次数，也不要改旧的 Camp 合约 |
