# D5（2026-11-20）定时任务小实验：Cron100 → Sepolia，最多 2 次

这份说明给 Windows PowerShell 用。合约、测试和脚本都在仓库里，部署要在你自己的电脑上跑。这里没有填交易哈希。公开网络上没有部署。本地用 Foundry 1.9.0 对 Lasna 和 Sepolia 做了分叉，只在 `127.0.0.1` 上跑过四个脚本：部署 Reactive、部署 Callback、`setRecipient`、`stop`，并确认脚本会拒绝旧的 D3/D4 地址。分叉上的合约地址不能当作业地址。没有读取私钥。

## 这次做的是哪条链路

```
Lasna Cron100（约每 100 个区块）
        │  D5CronReactive.react()
        ▼
Lasna 请求回调（SYSTEM.requestCallbackV_1_0）
        │  Sepolia Callback Proxy 投递
        ▼
Sepolia D5CronCallback.onTick()  发出 Ticked
```

第 2 次请求回调时，同一笔 `react()` 会按订阅时的六个参数调用 `unsubscribe`。之后 `subscribed = false`、`stopped = true`、`remaining = 0`。再送来的 tick 只更新 `lastCronNumber`，不再调用 `requestCallbackV_1_0`。

官方仓库里没有可以直接交作业的脚本：

- 本仓库原来的 `starter/script/Deploy.s.sol` 监听的是 `Ping`，不是 Cron。D3/D4 的 `CampOrigin`、`CampReactive`、`CampCallback` 这次没有改。
- `reactive-smart-contract-demos` 主分支的 `src/demos/cron/CronDemo.sol` 使用 `vmOnly` 和 `emit Callback`，那是旧架构。
- 同仓库 `omni` 分支的 `src/micro-demos/Cron.sol` 是现在要跟的写法：`AbstractReactive`、`onlySystem`、`SYSTEM.subscribe`、`requestCallbackV_1_0`，并有 `pause()` / `unsubscribe`。它的回调目标是 Lasna 上的自己，没有 Sepolia 合约，也没有「最多 N 次」。`CRON.md` 只有部署、暂停、恢复三条命令。

本实验把 Omni `Cron.sol` 的 Cron100 常量和退订方式，接到本仓库已有的 Sepolia 回调写法上，并把上限做成构造参数，部署脚本默认是 2。

2026-11-20 在 Lasna 上读过 Cron100 日志（只读）：`topic0` 是 `keccak256("Cron100(uint256)")`，`data` 为 `0x`，区块号在 `topic1`。相邻两次（区块 8813600 与 8813700）的时间戳相差 105 秒。文档里「number 在 data」的说法和这条链当前的事件不一致，合约两种布局都解码，优先用 `topic1`。

## 测试币：不必补到 0.05 ETH

2026-11-20 只读。钱包 `0x5576d42Fe13888b7f084190934abD07F061225fe`：Sepolia **0.019937999163426599 ETH**，Lasna **0.471372299999213723 lREACT**。旧合约没有发交易。

Sepolia Proxy `0xAa14d9Cd0f788Ca23d11805986C1d8bd035D23b4` 当时的收费参数：`_gasPriceCoeffPer1000 = 1100`，`_extraGas = 150000`。费用是 `baseFee × 1.1 × (实际消耗 gas + 150000)`，按实际消耗算，不是按 0.02 ETH 预扣。从区块 12172594 到 12175494，base fee 一直在 **12–20 wei**。按 80000 gas 的 `onTick` 估算，两次回调大约 **760 万 wei（0.0000000000076 ETH）**。`0.001 ether` 和 `0.002 ether` 都盖得住当前价格，也盖得住 base fee 涨到大约 1–2 gwei 的情况。0.05 ETH 是按几十 gwei 预留的，这次不用补。

`.env` 里请写 **wei 整数**。Foundry 自己的 `.env` 解析器碰到 `0.002 ether` 这种带空格的值会整份文件都不加载。`d5-lab.ps1` 如果看到这两个金额写成 `0.002 ether`，会在调用 forge 之前只把这两行改成 wei。

| 变量 | 含义 | 建议值 | wei |
|---|---|---|---|
| `D5_CALLBACK_FUND` | 部署时转进 Sepolia 回调合约的 ETH | 0.002 ether | `2000000000000000` |
| `D5_CALLBACK_FUND` | 更小的可用值 | 0.001 ether | `1000000000000000` |
| `D5_REACTIVE_FUND` | 部署时转进 Lasna 合约的 lREACT，只付 react | 0.10 ether | `100000000000000000` |
| `D5_REACTIVE_FUND` | 今天也能过钱包检查的更大值 | 0.15 ether | `150000000000000000` |

脚本默认是 **0.002 ETH** 和 **0.10 lREACT**。0.002 从 0.0199 里转走之后，钱包还剩约 0.0179 ETH 付部署。回调合约创建字节码大约 1.6 KB。

Lasna 系统合约 `_extraGas = 100000`，系数 1000/1000，base fee **100 gwei**。两次 react 按每次 200000 gas 估算大约 **0.06 lREACT**，所以合约里放 0.10 够用。部署交易的费用从钱包扣。本地分叉上 `DeployD5Reactive` 估算 1,108,762 gas，按 2 倍 base fee（200 gwei）预留约 0.222 lREACT；`setRecipient` 实际约 80,456 gas。0.10 + 0.222 + 0.02 ≈ 0.34，低于 0.471。0.15 今天大约需要 0.39，也低于 0.471；base fee 涨到大约 150 gwei 时，0.15 会过不了钱包的费用上限检查，0.10 仍然勉强够。默认用 0.10。

水龙头合约（Ethereum Sepolia）：`0x9b9BB25f1A81078C544C829c5EB7822d747Cf434`。1 ETH 换 100 lREACT。

## 部署顺序

1. `preflight`：只读余额、收费参数、编译和测试。不广播。
2. `deployReactive`：Lasna 部署 `D5CronReactive`。这一步不订阅。
3. `deployCallback`：Sepolia 部署 `D5CronCallback`。构造参数是官方 Proxy 和上一步的地址。
4. `bind`：回到 Lasna 调 `setRecipient`。这一步才订阅 Cron100。
5. 等大约 5 分钟。中间不用发 Ping。
6. `verify`：只读 `executed`、`count` 和 `Ticked` 日志。
7. 只有 `subscribed` 仍是 true 时，才单独跑 `StopD5`。

`DeployD5Cron.s.sol` 会拒绝这三个旧地址，并且在 `setRecipient` / `stop` 之前读 `MAX_EXECUTIONS()`，避免对旧的 `CampReactive` 调用同名函数。

## PowerShell

把压缩包解进现有仓库即可，不必为了这批新文件切分支。脚本自己会把 `C:\Users\laven\.foundry\bin` 加到 PATH，从 `starter\.env` 读取配置，命令行不出现私钥。它只用 UTF-8（无 BOM）改 `D5_REACTIVE_ADDR` 和 `D5_CALLBACK_ADDR`。地址已经有值，或者 `broadcast` 里已经有对应的 CREATE 回执时，部署阶段会停下来：不会再发一笔，也不会把失败回执当成成功跳过。公开回执只从 `starter\broadcast\DeployD5Cron.s.sol\<chainId>\run-latest.json` 读，不读 `cache`。

```powershell
Set-Location -LiteralPath "D:\reactive camp\reactive-builder-camp\starter"
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage preflight
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage deployReactive
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage deployCallback
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage bind
```

第一次部署的回调合约不能复用。`_CALLBACK_SENDER` 在构造时写成旧的 Reactive 地址，新的 Reactive 地址对不上，旧回调会拒绝。旧 Reactive 的次数已经用完，也没有加次数的函数。两边都要重新部署。旧回调里剩下的约 0.002 ETH 和旧 Reactive 里剩下的 lREACT 取不出来，金额很小，不要去动那两个地址。

已经写过 `D5_REACTIVE_ADDR` 和 broadcast 时，先归档再部署。这一步不读 cache，不删其他 `.env` 键，也不覆盖已经记下的失败地址：

```powershell
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage prepareRerun
```

它把 `broadcast\DeployD5Cron.s.sol` 挪到 `broadcast\d5-archive\<时间>\`，把当前两个 D5 地址抄到 `D5_FAILED_REACTIVE_ADDR` 和 `D5_FAILED_CALLBACK_ADDR`，然后只清空这两个当前地址。脚本不会改金额。归档后把 `D5_REACTIVE_FUND` 写成 `60000000000000000`（0.06 ether 的 wei），再从 `preflight` 开始。第一次两次 react 实际花了约 0.034 lREACT。按现在 Lasna 余额和 2 倍 base fee 上限，0.10 会超，0.06 够。

`bind` 成功后等大约 5 分钟：

```powershell
powershell -ExecutionPolicy Bypass -File .\script\d5-lab.ps1 -Stage verify
```

想改成 0.001 ETH 时，在 `.env` 里加一行 wei。变量名是 `D5_CALLBACK_FUND`，单位是 wei，不是 ETH 的小数：

```
D5_CALLBACK_FUND=1000000000000000
```

`.env` 里原有的 `PRIVATE_KEY`、`SEPOLIA_RPC_URL`、`LASNA_RPC_URL`、`CALLBACK_PROXY`、`ORIGIN_ADDR`、`REACTIVE_ADDR`、`CALLBACK_ADDR` 都不要改。D5 只用 `D5_REACTIVE_ADDR` 和 `D5_CALLBACK_ADDR`。

紧急退订不在自动化脚本里：

```powershell
forge script script/DeployD5Cron.s.sol:StopD5 --rpc-url https://lasna-rpc.rnk.dev/ --broadcast --chain 5318007
```

## 为什么不会一直扣到余额耗尽

Cron 订阅只要还在，每个 tick 都会收费，即使 `react()` 里什么都不做。所以有四层止损：

1. **部署时不订阅。** 订阅发生在 `setRecipient`。部署回调合约的那几分钟不会烧 lREACT，也不会把 2 次额度用掉。
2. **上限是 2，而且写死在 `MAX_EXECUTIONS`。** 没有增加次数的函数。第 2 次请求回调之前就把 `remaining` 减到 0，并用和订阅完全相同的参数 `unsubscribe`。
3. **退订之后再进来的 tick 直接 return。** 不调用 `requestCallbackV_1_0`。节点正常的话，退订之后就不会再投递；万一有一笔已经在路上，这一层也不会再发回调。
4. **`stop()` 可以手动退订。** 只有主人能调，重复调用是空操作。跑完 2 次之后 `subscribed` 已经是 false，就不必再调。

不要改用 Cron1 或 Cron10。Cron1 大约每秒一次，在你发现没停之前就会把测试币扣掉。本实验只有 Cron100。

回调那边的 ETH 只在真正投递时支付。`onTick` 不因为「已经两次了」而 revert，因为失败的回调也收费。停止请求是 Lasna 合约的责任。

## 本地测试覆盖

`forge test --match-path test/D5Cron.t.sol -vv` 覆盖：

- 链不是 Lasna、或上限为 0 时，构造函数失败
- 绑定回调地址之前不订阅；绑定后只订阅一次 Cron100
- `react()` 只接受系统合约；别人不能 `setRecipient` / `stop`
- 直接调用 `onTick` 失败；Proxy 注入了错误的 reactive 地址也失败
- 第 1 次用线上的 topic1 布局，第 2 次用 data 布局，都会请求回调；第 3 次不再请求
- 退订的六个参数和订阅相同
- payload 第一个地址是 `address(0)`，目标链是 Sepolia，gasLimit 为 400000
- 不发出已经废弃的 `Callback` 事件
- `stop()` 之后再来 tick 不再请求；停止后不能再 `setRecipient`
- Mock Proxy 投递两次后，回调合约 `count == 2`

## 常见情况

| 现象 | 处理 |
|---|---|
| `WrongChain` | RPC 不是 Lasna。命令里保留 `--chain 5318007` |
| Lasna `lastReactBlock` 一直是 0 | 还没到下一个 100 的倍数区块，或 `setRecipient` 没成功。等满 5 分钟再查 `subscribed` |
| `executed` 增加了，Sepolia `count` 仍是 0 | 回调合约没有 ETH、Proxy 不是 `0xAa14…`、或 `D5_REACTIVE_ADDR` 填错。填错 reactive 地址只能重新部署回调合约，再重新 `setRecipient` |
| `debt` 大于 0 | 给该合约转对应的测试币，或调用 `coverDebt()` |
| 5 分钟后 `subscribed` 仍是 true，而且 `executed` 已经是 2 | 跑上面的 `StopD5` |
| 想再做一轮 | 重新部署一对新合约。不要给这个合约加次数，也不要改旧的 Camp 合约 |
