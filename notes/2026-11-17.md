
输出：

```

```

```bash
cast call 0x8888888888888888888888888888888888888888 "_extraGas()" --rpc-url https://lasna-rpc.rnk.dev/ | cast to-dec
```

输出：

```
100000
```

```bash
cast call 0x8888888888888888888888888888888888888888 "_maxChargeGas()" --rpc-url https://lasna-rpc.rnk.dev/ | cast to-dec
```

输出：

```
50000
```

这三个数的意思：

- `_gasPriceCoeffPer1000` 是 1000，系数要再除以 1000，所以现在是 1。
- `_extraGas` 是 100000，每次计费都要加上的固定附加 gas。
- `_maxChargeGas` 是 50000，它不进入费用公式，只是系统向合约收款时可用的 gas 上限。

## 1. 一次 react() 的费用怎么算？

费用公式是：

fee = 基础 gas 价格 × 系数 × (实际消耗 gas + 固定附加 gas)

其中基础 gas 价格取交易 gas 价格和区块基础费用里较大的那个；系数就是上面查到的 1000，再除以 1000，所以现在等于 1；固定附加 gas 是 100000。

因此在当前 Lasna 上，一次 `react()` 的费用大约是：

fee = 基础 gas 价格 × 1 × (这次实际用掉的 gas + 100000)

就算 `react()` 失败回滚，也按实际消耗照样收费，不会退款。所以条件不满足时应该正常结束，而不是让函数失败。

## 2. balance、reserves、debt 分别是什么？为什么只要有一点 debt，合约就停止执行？

- balance（余额）：合约自己口袋里的钱。
- reserves（预付）：先交给系统合约保管、专门用来付手续费的额度。
- debt（欠款）：已经产生但还没付清的手续费。

扣费会先花预付，预付没了才产生欠款；充值会先还欠款，还清了才变成预付。直接把币转到合约只增加余额，不会自动还欠款。

只要 debt 大于 0，系统在执行前就会先检查欠款，然后直接跳过：不再调用 `react()`，目标链也不会再投递回调。这是静默停止，看起来像什么都没发生。所以要保持预付充足，或者用 `depositTo()` 还清欠款后，自动化才会恢复。
